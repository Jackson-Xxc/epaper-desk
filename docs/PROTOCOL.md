# EPD-nRF5 蓝牙协议笔记

本文记录墨水屏桌面当前适配的 BLE 接口，来自 EPD-nRF5 兼容固件和实际设备验证。
它不是通用电子价签协议规范。

## GATT

```text
设备名称前缀     NRF_EPD
Service UUID     62750001-d828-918d-fb46-b6c11c675aec
Characteristic   62750002-d828-918d-fb46-b6c11c675aec
Version UUID      62750003-d828-918d-fb46-b6c11c675aec
```

控制命令和图像数据写入同一个 Characteristic。程序优先使用确认写入，以降低 Windows
蓝牙栈在连续长数据发送时出现 `GATT operation failed for unknown reason` 的概率。

## 常用命令

| 命令 | 字节 | 用途 |
| --- | --- | --- |
| INIT | `01` | 初始化面板 |
| CLEAR | `02` | 清空屏幕 |
| REFRESH | `05` | 触发整屏刷新 |
| SLEEP | `06` | 面板休眠 |
| SET_TIME | `20` | 同步时间 |
| WRITE_IMAGE | `30` | 写入色层数据 |
| SET_CONFIG | `90` | 写入配置 |
| SYS_RESET | `91` | 系统重启 |
| SYS_SLEEP | `92` | 系统休眠 |

## 图像格式

分辨率为 400 × 300，每 8 个横向像素组成一个字节，因此每个色层为：

```text
400 × 300 ÷ 8 = 15,000 字节
```

程序生成两个 1 bit 色层：

- 黑白层：黑色像素清除对应 bit；
- 红色层：红色像素清除对应 bit；
- 白色像素在两个色层中都保持为 1。

当前颜色阈值在 `src/renderer.js` 的 `canvasToPlanes()` 中实现。

## 图像分包

每个图像包由 2 字节协议头和图像数据组成：

```text
[0x30, plane_flag, ...image_bytes]
```

| 色层 | 第一包 flag | 后续包 flag |
| --- | --- | --- |
| 黑白 | `0x0f` | `0xff` |
| 红色 | `0x00` | `0xf0` |

虽然设备会报告接近 244 的 MTU，Windows 稳定路径仍把完整 GATT value 限制为 200 字节：

```text
2 字节协议头 + 198 字节图像数据
```

每包使用确认写入并等待 80 ms。发送顺序为：

1. `INIT`
2. 黑白层全部数据
3. 红色层全部数据
4. `REFRESH`

## 兼容性提示

- 清屏、同步时间能成功并不代表长图像传输一定稳定；后者更容易暴露蓝牙控制器队列问题。
- 减小包长通常比增加重试次数更有效。
- 修改包长、flag 或色层顺序前，应先保留一份已知能刷新的固件与网页工具作对照。
- 不同尺寸或固件分支可能使用完全不同的命令和色层方向。
