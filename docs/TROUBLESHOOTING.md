# 故障排查

## 找不到 `NRF_EPD`

- 确认电子价签已重新进入广播状态。
- 让设备靠近电脑，避免同时被手机或其他浏览器占用。
- 在 Windows 设置中移除旧的缓存配对记录后重新扫描。
- 使用支持 Web Bluetooth 的新版 Chrome / Edge 或本项目的 Electron 版本。

设备选择器中出现大量“未知设备”是 Windows 返回附近广播的正常现象。应用使用
`NRF_EPD` 名称前缀过滤；浏览器自己的系统选择窗口不一定隐藏所有未知设备。

## `Connection attempt failed`

1. 关闭占用设备的网页、手机蓝牙工具或另一份程序实例。
2. 让价签重新上电或重新进入广播。
3. 关闭再打开 Windows 蓝牙。
4. 如果蓝牙耳机也同时卡顿，优先检查主板天线、USB 3.0 干扰、蓝牙驱动和 2.4 GHz 拥堵。

## 短命令成功，传图失败

这是最常见的 Windows GATT 队列问题。当前稳定路径已经采用：

- 提供自动、快速、均衡、稳定和极稳五档传输策略；
- 自动档默认使用 160 字节图像分包，连续 6 个无响应写入后发送 1 个确认写入；
- 默认包间隔 25 ms，确认写入后等待 150 ms，避免塞满 Windows 蓝牙队列；
- 进度只在确认写入后推进，避免把进入本机队列误认为设备已收到；
- 失败后重新连接，并依次降低到 120 字节和 80 字节分包后从头完整重传。

运行记录中若仍固定在某个包失败：

- 把设备移到距天线 0.5～1 米处测试，贴得过近也可能不稳定；
- 暂时断开蓝牙耳机、手表和手柄；
- 更新主板或 USB 蓝牙适配器驱动；
- 避免把蓝牙天线紧贴 USB 3.0 硬盘、集线器或 Wi-Fi 天线；
- 用已知可用的手机网页工具验证屏幕和电池。

## 传输完成但屏幕不刷新

- 检查日志是否已发送 `REFRESH`，并等待电子墨水整屏刷新完成。
- 使用“清空屏幕”验证控制命令。
- 如果图像数据传完但刷新命令失败，重新唤醒设备后再发送一次。
- 确认固件尺寸和色层格式与 400 × 300 黑白红协议一致。

## 飞书登录或排班异常

见 [飞书 OAuth 配置](FEISHU_SETUP.md)。排班日历名称不含关键词时，可填写附加日历 ID，
或在 `dayStatus()` 中调整适合自己公司的事件命名规则。

## Codex 周额度读取失败

该功能依赖本机 Codex 登录和非公开接口。确认当前 Windows 用户已经登录 Codex；
如果仍失败，请关闭自动读取并手动填写剩余比例与重置时间。
