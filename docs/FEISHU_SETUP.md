# 飞书 OAuth 配置

墨水屏桌面只支持用户授权，不需要把飞书账号密码交给程序。

## 1. 创建应用

1. 打开飞书开放平台，创建“企业自建应用”。
2. 在“凭证与基础信息”中取得 App ID 和 App Secret。
3. 确保需要使用软件的账号位于应用可用范围。

## 2. 开通用户权限

在权限管理中开通：

```text
calendar:calendar:readonly
task:tasklist:read
offline_access
```

权限必须作为“用户身份”权限开通。完成后发布一个应用版本，否则授权页可能仍提示权限不足。

## 3. 设置回调地址

在应用安全设置的重定向 URL 列表中添加：

```text
http://127.0.0.1:37691/feishu/oauth/callback
```

必须完全一致，包括协议、端口、路径，不要追加斜杠。

## 4. 登录

1. 打开墨水屏桌面的“内容”页。
2. 展开“应用配置 / 临时 Token 方式”。
3. 输入 App ID 和 App Secret。
4. 点击“登录飞书”，在浏览器中完成授权。
5. 返回软件，等待“飞书已登录”。

App Secret、访问令牌和刷新令牌会使用 Electron `safeStorage` 写入当前 Windows
用户的数据目录，不会写进项目目录或运行日志。

## 5. 排班日历

程序始终会读取：

- 当前用户的主日历；
- 名称包含“排班、班表、值班、轮班”的可见日历。

高级配置中的“附加日历 ID”只会增加一个读取来源，不会覆盖上述自动发现结果。
即使保留了旧版本填写的主日历 ID，排班日历也仍会正常读取。

当前判定规则是为本项目使用场景设计的简单规则：

- 排班事件标题或描述包含“休息、休假、放假、假期、节假日、请假、调休”时显示“休”；
- 同一天的其他排班事件显示“班”；
- 没有排班事件时使用法定节假日、法定调休和周末作为后备。

不同企业的排班命名方式可能不同，需要在 `src/renderer.js` 的 `dayStatus()` 中调整匹配规则。

## 6. 任务清单

“任务清单名称”必须与飞书任务中的清单名称一致。程序读取清单内任务并按创建时间倒序，
只把最新的未完成任务放进 400 × 300 主内容区。

## 常见错误

### 重定向 URL 有误（20029）

确认飞书后台登记的 URL 与软件显示的回调地址逐字一致，并确认应用已发布。

### 权限不足（20027）

检查用户身份权限是否包含日历只读、任务清单只读和 `offline_access`，然后重新发布并授权。

### PKCE code challenge failed

关闭旧授权页，从软件重新点击“登录飞书”。授权请求只能使用一次，不要刷新或重复提交旧回调页。

### 已登录但读取为 0 项

1. 检查软件状态中是否显示识别到的排班日历名称。
2. 确认排班日历对当前账号可见。
3. 软件默认读取从现在开始的未来 45 天；过去日程不会计入。
4. 如日历名称不含排班关键词，可在高级配置中填写“附加日历 ID”。
